# 批量审片

## 通用流程

1. 建立素材清单：原文件名、时长、分辨率，以及用户已有的镜头号和版本号。默认不替用户创造新编号。
2. 在可用时计算完整文件内容哈希。哈希相同的文件视为精确重复：只审查一次，保留所有原文件映射，不重复计入排名、平均分或问题统计。报告用一个原文件名作为主显示名，并在括号中列出重复文件。哈希不同但画面相似的素材不能自动当作重复版本。
3. 每条独立内容分别检查，先形成单条结果，不能因为需要排名而省略严重问题。
4. 根据模式执行横向检查：候选版本比较或连续镜头衔接。
5. 汇总共性问题、异常个例、返修顺序和推荐选择。

## 候选版本 `variants`

只比较同一镜头号内的版本。排序优先级：

1. 先把用户的分镜拆成可观察的硬条件和偏好条件。硬条件示例：必须出现的主体、动作、地点、数量、先后关系和情绪结果；偏好示例：镜头风格、光线、节奏和景别。
2. 缺失核心硬条件的版本不能仅凭技术质量排在完整表达剧情的版本之前，除非完整版本存在阻止使用的严重损坏。
3. 在满足硬条件的候选中，优先选择没有 `critical` 或 `major` 技术损坏的版本。
4. 再比较偏好条件、返修成本和证据置信度。
5. 分数仅作为辅助，不用微小分差制造虚假精度。

比较表应逐项展示每个硬条件是否满足，并区分：`符合`、`部分符合`、`不符合`、`无法确认`。情绪要求需要可见表演证据；“面对面”“哭泣”等不能仅从故事意图推断。

输出每组的首选、备选、淘汰项和选择理由。若不同版本各有优势，说明适用场景，不强行选唯一冠军。

## 连续镜头 `sequence`

按镜头顺序检查跨镜连续性：人物身份、服装、道具状态、空间方向、视线、动作接点、光线、天气、色调和叙事因果。跨镜问题同时引用前后两个素材及时间点。

## 汇总报告

必须包含：

- 总览：数量、可发布、后期可修、需重生成、淘汰数量。
- 上传文件数、独立内容数与重复文件映射。
- 排名或镜头顺序表。
- 每条视频的发布结论、主要问题和下一步。
- 共性问题与可能的生成阶段根因。
- 返修队列：先修影响最大且成本最低的项目。
- 无法横向比较或证据不足的项目。

## 名称显示

- 面向用户的标题、表格、排名和返修队列默认使用原文件名。
- 如果用户已经使用 `S01_V01` 等编号，则原样保留，不能重新编号。
- 只有素材量大到原文件名无法清楚引用，或用户明确要求编号时，才创建短编号；即使如此也应让原文件名保持可见。
- 程序内部可以使用稳定 ID，但内部 ID 不应出现在普通用户报告中。

可将逐条 JSON 结果交给 `scripts/batch_report.py` 生成一致的 Markdown 汇总骨架。
