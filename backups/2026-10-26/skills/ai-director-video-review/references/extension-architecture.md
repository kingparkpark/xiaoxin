# 扩展架构

```text
视频/创作上下文
  -> 素材探测（时长、帧率、镜头边界）
  -> 自适应取帧（固定间隔 + 转场 + 异常区间）
  -> 视觉观察（单帧描述 + 跨帧跟踪）
  -> 规则判定（五大模块 + 创作意图）
  -> 问题聚合与评分
  -> Markdown/JSON 报告
```

## 可替换接口

- `FrameExtractor`：从视频生成带时间码的帧与片段；后续可用 FFmpeg 实现。
- `VisionAnalyzer`：返回观察事实、对象身份和跨帧变化；适配任意支持图像或视频的多模态模型。
- `RuleEngine`：把观察与标准库、创作上下文结合，区分缺陷与有意变化。
- `ReportRenderer`：将统一结果渲染为 Markdown、JSON 或网页。

## 数据边界

中间结果必须保留来源时间码、模型版本和置信度，便于复查。不要把视觉模型的自然语言描述直接当成最终判定。涉及未成年人、私密素材或客户未发布内容时，应由接入方定义存储、保留和第三方传输策略。

## 建议迭代顺序

1. 用人工提供的关键帧验证规则与报告模板。
2. 接入 FFmpeg，增加镜头切换和自适应取帧。
3. 接入视觉模型，先产出观察事实，再由规则层判定。
4. 增加 JSON 校验、问题合并和自动 Markdown 报告。
5. 用已标注样片评估召回率、误报率、时间定位误差和返修建议可执行性。
