# 输入路由与参数处理

## 接收输入

最小可用输入只有**基础画面（scene）**。情绪或叙事目标（emotion）未提供时，可以从画面谨慎推断，并在输出中说明该推断。限制条件、指定导演、平台、时长、画面比例和参考图均为**可选**输入；缺少其中任一项都不得阻止生成或要求补充。

将输入标准化为：画面事实、叙事目标/情绪、限制条件、导演意图、已知生成元数据，以及参考图状态。先保留用户明确给出的事实和限制，再作可见、可执行的摄影决策。

## 模式选择

- 没有参考图：进入**文生视频**（text-to-video）。完整描述所有可见事实、人物与环境、动作、镜头行为、光线和连续性。
- 有参考图：进入**图生视频**（image-to-video）。将人物身份与外观、服装、环境及起始构图视为锁定条件，除非用户明确要求改变；重点描述后续动作、运镜、环境变化和连续性，不擅自改写已经确定的画面。

## 平台、时长与比例

- 平台、时长、画面比例都是可选元数据。已知平台用于适配支持的表达或字段；已知时长限制动作数量与节奏；已知比例影响主体位置、留白和空间关系。
- 缺少平台、时长或比例时，**不追问**。根据画面复杂度、叙事节奏和空间关系推断推荐值，并在 Prompt 外单列“推荐参数”。
- 默认不把平台名称、秒数或比例写进 Prompt 正文。只有这些信息会实质改善目标模型对时序或构图的理解时，才在“平台适配版 Prompt”中自然语言说明，并解释为何需要显示。

## 输出交接

路由完成后，向后续流程提供：`mode`（文生视频或图生视频）、已知元数据、缺失元数据的推荐候选、锁定条件、画面事实、情绪/叙事目标与限制条件。输出按以下部分组织：

1. 风格匹配
2. 镜头决策
3. 可执行 Prompt
4. 负面约束
5. 推荐参数（仅列出用户未提供的项目）
